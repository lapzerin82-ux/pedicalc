# PediCalc — Android app

A from-scratch implementation of Dr. Bashar Ibrahim's Pediatric Clinical
Calculator (drug dosing + clinical decision-support), redesigned for a real
installed Android app and packaged as a Capacitor project.

## What's here

- `www/` — the app itself: plain HTML/CSS/JS (no framework, no build step).
  - `js/data.js` — the 15 calculators + 221-drug BNFC-sourced dosing database,
    ported verbatim from the approved design (`project/Pediatric Clinical
    Calculator.dc.html`). Math/data unchanged.
  - `js/app.js` — state machine and view-model logic, ported from the same
    source's `Component` class (screen routing, calculators, patient context,
    saved list, search).
  - `js/render.js` — hand-written DOM rendering for the 5 screens (home,
    category, calculator, saved, patient), replacing the design tool's
    internal template runtime.
  - `css/styles.css` — the "Modernist ink" visual system (white cards, 2px
    ink rules, red reserved for the dose figure and cautions) the user chose
    during design, refined for a native app: bigger touch targets, safe-area
    insets, no phone-frame mockup, hidden number-input spinners, subtle
    screen-transition and press-state motion.
  - Also installable directly as a PWA (`manifest.json` + `sw.js`) if you'd
    rather skip the APK step entirely.
- `android/` — native Android project generated by Capacitor, wrapping
  `www/` in a WebView. Icons and splash screens are generated from the
  app's own "Rx" brand mark at every density.
- `assets/` — the 512×512 source logo used to generate the Android icons.

Verified: all 15 calculators and all 221 drug entries compute without error
(headless test + real Chromium screenshots across every screen, several
calculators, and both calculated and reference-mode drugs).

## Finishing the build

Everything is ready except the final compile step. **This sandbox's network
policy blocks Google's Maven repo** (`dl.google.com`, and `maven.google.com`
redirects straight back to it) — that's where the Android Gradle Plugin and
SDK components live, so `gradlew` gets to dependency resolution and stops
there. I confirmed this by actually running the build here and by testing
every mirror I could think of (maven.google.com, jitpack.io, androidx.dev,
Maven Central) — none of them can substitute, since AGP is only published
through Google's own repo and this sandbox's egress allowlist doesn't
include it. Node, Java 21, and Gradle 8.14 are otherwise all present and
working, and the project itself configures correctly right up to that point.

**Option A — CI (no local setup needed):** push this repo to GitHub and the
included `.github/workflows/android-build.yml` builds a debug APK
automatically (GitHub-hosted runners have normal internet access, so this is
where the build actually completes). Download the APK from the workflow
run's Artifacts. You can also trigger it manually from the Actions tab
("Run workflow").

**Option B — locally**, on any machine with normal internet access:

```bash
cd app
npm install
npx cap copy android      # re-run after any change to www/
cd android
./gradlew assembleDebug   # -> app/build/outputs/apk/debug/app-debug.apk
```

Or simpler: open the `android/` folder in Android Studio and hit Run/Build —
it will fetch the SDK components itself on first open.

For a Play Store-ready **signed release APK/AAB**, use Android Studio's
Build > Generate Signed Bundle/APK, or `./gradlew bundleRelease` with a
signing config (either locally or by extending the CI workflow with your
signing secrets).

## Notes

- No feature changes were made beyond the visual redesign — screen flow,
  calculators, and dosing math match the approved design exactly. Two small
  additions were necessary for correct behavior as a real installed app
  (not part of the visual redesign itself):
  - Android hardware/gesture back-button handling (mirrors the in-app back
    arrows instead of exiting the app).
  - Saved calculators and patient context (weight/height/age/sex/name)
    persist across app launches via `localStorage`, so they survive closing
    the app — verified with a full page-reload test. Everything else
    (current screen, search text, in-progress field values) stays
    in-memory only, matching the original design.
